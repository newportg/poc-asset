OVERVIEW

Explore property records and connections

Asset Explorer is a browser-native proof of concept for real-estate Asset records. It demonstrates searchable records for land parcels, sites, estates, buildings, and units, with location details, typed Asset links, and sample Instruction references.

The main app has no backend or build step. Records are stored in the browser, while address lookup and map tiles use external services when requested or displayed.

ASSET MODEL

Asset records and typed links

Each Asset has a stable demo ID, name, type, record status, location, and optional descriptive or external identifier fields. Location includes latitude, longitude, coordinate reference system, source, capture date, and precision.

  • Supported relationship types are part_of, located_on, and associated_with.
  • Links have a source and effective dates. Ending a link retains it with Ended status and an end date.
  • A Unit must have an active part_of relationship to a Building. A Building's Units are derived, not stored as duplicate inverse links.
  • Instruction references and WIP counts are static sample associations; the app does not create or edit them.
USING THE APP

Search and explore records

  1. Search by Asset ID, external reference, name, address, locality, country, description, Sector, or Site association. Filter by Asset type and record status.
  2. Select a record to view its location and provenance, relationships, Instruction references, sample WIP count, and related Assets.
  3. Choose New asset to create a record or Edit record to update its details and an active relationship.
  4. For relationship history, use End link. The old link is retained rather than deleted.
  5. Use Reset sample data to restore the fictional starting records and discard local edits. Theme and Loqate key preferences are stored separately.

The detail pane zoom controls adjust its content from 80% to 140% independently of the catalogue and page zoom.

ADDRESS LOOKUP

Search and verify an address with Loqate

In the create/edit form, choose a search country and enter an address or postcode. Live search requires a Loqate API key. Select a match to retrieve its details and fill the Asset form with the address, locality, country, and coordinates when returned.

The API key is saved in this browser's localStorage under loqate_api_key. Browser storage is not a secure secret store. The key name matches the Address POC, but browser storage is isolated by origin, so sharing only applies when both apps use the same origin.

Coordinates returned by the lookup are stored as WGS 84 (EPSG:4326). A verified address may not include coordinates; in that case, enter valid latitude and longitude before saving.

MAPS

Preview and open a location map

Asset coordinates are used to center a Leaflet map preview in the details panel. Click the preview to open a larger interactive map. The map uses OpenStreetMap tiles and attribution; map rendering requires internet access.

Map interpretation The map plots the stored latitude and longitude. It does not transform other coordinate reference systems, show property boundary geometry, or verify title, ownership, or legal boundaries.
IMPLEMENTATION

Files and local checks

  • src/index.html and src/documentation.html are static pages published together from src/.
  • src/app.js handles the interface, forms, persistence, Loqate interactions, and maps. src/assets.js contains sample fixtures, model validation, search helpers, and derived Unit lookup.
  • src/loqate-client.js builds address search and retrieval requests. Leaflet is loaded from its CDN; tiles are requested from OpenStreetMap.
  • tests/assets.test.mjs covers model rules and derived relationships; tests/loqate-client.test.mjs covers Loqate request behavior.

Open src/index.html in a modern browser or serve the src/ directory with a static web server. No build or install step is needed. Run the tests from the repository root with node --test tests/*.test.mjs.

DATA AND LIMITATIONS

What this POC does not provide

Asset records are stored in browser localStorage under poc-asset.records.v1; the theme is stored separately under poc-asset.theme.v1. Data is not encrypted, backed up, or synchronized. Browser users can inspect or change stored data.

  • No authentication, authorization, server persistence, or multi-user access
  • No production audit guarantees or historic snapshots of Asset fields; local demo audit entries are illustrative
  • No boundary geometry or authoritative boundary source, Party links, or editable matter/Instruction associations
  • No coordinate transformation for alternate coordinate systems
  • No inference of title, ownership, valuation, legal status, transaction inclusion, cadastral boundaries, or compliance outcomes

Use fictional demo data only. Do not enter real, confidential, or personal information.
